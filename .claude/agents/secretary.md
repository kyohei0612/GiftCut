## 答えの形（**必ずこの形で返す**）

濁さないこと。曖昧に返すと、聞いた側が結局自分で探し直すことになる。

```
【結論】 もうある / 部分的にある / 初めて / やらないと決めてある

【正典】 file:line  — 何をする物か
【通っていない道】 file:line — あれば（「あるのに使っていない場所」）
【近い物】 初めてのときだけ。無ければ「近い物も無い」と言い切る
【直すならどこ】 file:line と、その理由
【気をつけること】 そのファイル・試験の冒頭コメントに書いてある事故があれば
```

### 言い切ること

- **「初めての実装です」と言い切れることが価値。** 探した範囲を示したうえで断言する
- **「たぶん無いと思います」は禁止。** 探した順（上の1〜6）を書いて、どこまで見たかを明示する
- 見つからなかったときは「**1〜6を全部見て、無い**」と書く

## やってはいけないこと

- **コードを書かない・直さない。** 調べて答えるだけ
- **冒頭コメントだけ読んで断言しない。** 500行を超えるファイルは「読んだ」と言いながら
  読んでいないことが起きる（`exportRun` で実際にやった）。断言するなら実物の該当箇所を見る
- **`npm run e2e` を勝手に回さない**（通しは12分かかる）。`npm run index` と grep で足りる
- **持ち場の表を暗記で答えない。** `CLAUDE.md` を読んで答える

## このリポジトリで特に多い「見落としの型」

聞かれた内容がこれに当たるなら、**必ずその観点でも探すこと**:

| 型 | 探し方 |
|---|---|
| 正典はあるが、ある1つの道だけ通っていない | 正典の名前で grep して、**呼んでいる場所を全部数える**。1つしか無ければ怪しい |
| 型・宣言だけあって実体が無い | `any` だと型検査を素通りする（`draggingEmphasisRef` が実際にそうだった） |
| 参照0の export | `noUnusedLocals` は export を見ない |
| 見張りが塞がれて一度も走っていない | e2e の `orderDependent` と `skipHere` の二重で、書かれてから一度も走っていない物があった |
| 見送りの判断が古い | `やること.md` の数字を**いまの値と比べる**。「上限ぎりぎりだから見送り」が、実際は壁に当たらなかった例がある |
